# interpersonal-writing（対人文章）

人に送る文章を、相手との関係と用件に合わせて書くためのスキル。中心はビジネスメール（企業の採用担当・取引先・教員・窓口）で、同じ判断をチャット・問い合わせフォーム・フリマの取引メッセージ・家族や友人とのやり取りにも使う。

考え方は二つ。第一に、敬語は「多いほど丁寧」ではない。相手との関係で決まる段階に合わせ、その段階の中でいちばん簡素な形を選ぶ。丁寧すぎる文面は、慇懃無礼や AI が書いた文に見える（根拠は references/sources.md）。第二に、文面の良し悪しは敬語より中身で決まる。相手の質問に答えているか、相手が次に何をすればよいか分かるか、日時や番号が正しいかを先に確かめる。

## 0. 設定ファイルを読む

最初に利用者の設定ファイル（profile）を探して読む。

1. 環境変数 `INTERPERSONAL_WRITING_PROFILE` があればそのパス
2. なければ `~/.config/interpersonal-writing/profile.md`

profile には、署名・相手ごとの段階・呼び方・言葉の癖・文面の渡し方が書いてある。profile の指定は、このスキルの既定より優先する。見つからなければ既定のまま進め、署名など本人にしか分からない情報は空欄（`［氏名］` のような角括弧）で残す。推測で埋めない。書式の見本は同じフォルダの `profile.example.md`。

## 1. 書く前に四つを決める

| 決めること | 中身 |
|---|---|
| 相手 | 誰か。相手との関係（家族・友人・身内の仕事仲間・内の目上・外の相手・外の初対面） |
| 媒体 | メール／チャット（LINE・Slack など）／問い合わせフォーム／フリマの取引メッセージとコメント。大学の学習支援システムのメッセージ（Moodle など）は「フォーム」として扱う |
| 用件 | 依頼・質問・お礼・お詫び・断り・催促・日程調整・報告・提出のどれか。1通に用件は一つが原則 |
| 言語 | 日本語か英語か |

依頼から読み取れないときは、関係と用件だけを一度で聞く。媒体と言語は依頼の文脈から判断してよい。

相手からのメールや案内への返事なら、その原文を最後まで読む。案内に手順書や URL があれば開く。日時・金額・番号・名前は原文から写し、記憶で書かない。済んだことか、これからのことかを確かめてから時制を選ぶ。

## 2. 段階を決める

`references/levels.md` を読み、関係から段階（0〜5）を、用件から重さ（軽い・普通・重い）を決める。段階は文末・挨拶・型を決め、重さはクッション言葉やお詫びの強さを決める。profile に相手ごとの段階があればそれを使う。

## 3. 型を当てる

段階と媒体に応じて、次のファイルを読む。必要なものだけを読み、全部は読まない。

| 条件 | 読むファイル |
|---|---|
| 段階3以上（敬語を使う） | `references/ja/keigo.md` |
| 媒体がメール | `references/ja/email.md` |
| 媒体がチャット（LINE・Slack など） | `references/ja/chat.md` |
| 媒体が問い合わせフォーム・学習支援システムのメッセージ | `references/ja/form.md` |
| 媒体がフリマの取引メッセージ・コメント | `references/ja/marketplace.md` |
| 用件が依頼・お詫び・断り・催促・日程調整・お礼・質問 | `references/ja/scenes.md` の該当する節（媒体がメールでなくても、入れる要素と順番は同じ） |
| 英語 | `references/en/email.md` |

媒体のファイルは形（宛名・挨拶・署名の要る要らない、長さ、媒体の決まり）を、scenes.md は中身（何をどの順で書くか）を決める。両方に当てはまるときは両方を読む。

## 4. 書く

本人の下書きを直すときは、本人が書いた事実と意図を残す。文を削る・事実を足すときは、何をなぜ変えたかを「6. 渡す」で一行ずつ添える。直す所が無ければ、そのまま返してよい（言葉を足して丁寧にしない）。

- 結論と用件を先に書く。経緯は後ろに短く
- 相手の質問には、全部に、聞かれた順に答える
- 相手が次にすること（返事・選択・提出）を一文ではっきり書く。選んでもらうなら選択肢を並べる
- 1文は短く。日時・場所・金額・手順は箇条書きにする
- 段階の中でいちばん簡素な形を選ぶ。「させていただく」「存じます」「恐れ入りますが」などは、1通に同じ語を重ねない
- お詫びは1回、はっきり書き、すぐ次の対応を書く。謝罪の言葉を繰り返さない
- 比喩・決めゼリフ・大げさな形容（「心より」「多大なる」の重ね）を使わない
- profile の呼び方・一人称・言葉の癖に合わせる

## 5. 検査する

書いた文面をファイルに保存し、機械で検査する（Python 3.11 以上・追加のライブラリは不要）。

```bash
python3 <このスキルのフォルダ>/scripts/check.py <文面のファイル> --level <0-5> --medium <email|chat|form|marketplace> [--context <profile の署名の種類>]
```

- 拾うもの：敬語の誤り（二重敬語・相手の動作への謙譲語など）、日付と曜日のずれ、丁寧すぎ（同じ語の重ね）、敬体と常体の混在、profile で使わないと決めた語。媒体ごとに、メールの宛名・名乗り・署名の抜け／チャットの挨拶だけの1通・全員への通知（@channel など）・不要な署名・改まりすぎ／フリマの外部への誘導・メルカリの外での支払い・個人情報
- 「誤り」と「型」は直す。「注意」は文脈を見て、直すか残すかを自分で判断する。残すなら理由を一言で言えるようにする
- 英語の文面は検査の対象外。`references/en/email.md` の「送る前の確認」で読み直す
- 検査を通った後、相手の立場で一度だけ読み直す：何の用件か最初の3行で分かるか／返事に必要な情報が揃っているか／この段階の相手に失礼な所や、逆に固すぎる所はないか

検査は文面が短くても省かない。

## 6. 渡す

- 送信はしない。送るのは本人
- profile に渡し方（保存先・ファイル名・クリップボードなど）の指定があれば従う。なければ、件名と本文を分けて会話に示す
- 迷った点（段階の判断、相手の名前の表記など）があれば、文面の後に一行ずつ添える
